# Generated editorial covers — do not treat these as photography

Every file in this folder is **drawn artwork**, generated by
`scripts/generate-guide-cover.mjs` from a guide's own metadata. Nothing here is
a photograph, a rendering, or a map, and nothing here depicts a real place.

These are not placeholders. Unlike the stand-ins listed in
`../README.md`, a cover is a finished asset: it is what a guide ships with when
Mikey has no authentic photograph for it. The order of preference never
changes:

> real LVINIT photography **>** generated editorial cover **>** the designed
> fallback panel in `components/GuideCard.tsx`

So when a real photo of a story does land, it replaces the cover — set
`image` + `imageAlt` and drop `imageMode` in `lib/content.ts`. Do not go the
other way, and do not swap an existing genuine photograph for a cover just to
make a row of cards look uniform.

## Regenerating

Covers are deterministic: the artwork is seeded from the slug, so re-running the
same command reproduces the same file. The command for each cover is recorded in
a comment next to its entry in `lib/content.ts`. For example:

```bash
node scripts/generate-guide-cover.mjs --slug first-summer-in-vegas --category "Moving Here" --subject "Las Vegas Summer" --out las-vegas-summer-editorial-cover.webp
```

Run `node scripts/generate-guide-cover.mjs --help` for the full options, and see
that file's header for the integrity rules the artwork is bound by — chiefly
that it draws no numbers, no real geography, and nothing photographic.
